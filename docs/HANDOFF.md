# 현재 작업 인계

2026-10-05. 현재는 **승인 목업을 기반으로 제작한 첫 플레이 버전 v0.1**이다. 사용자의 최신 지시는 “좋네 이 목업을 기반으로 게임 제작 시작해”다. 이전의 문서만/코드 금지는 해제되었다. 게임의 전체 완성으로 보고하지 않는다.

## 승인과 기준

- 새 PC 브라우저 게임. 이전 게임 코드·확률·단축키·데이터를 참고하지 않는다.
- High 추론 승인 유지. 일상적인 구현·검수마다 다시 승인받지 않는다.
- 여성 붓 검객 주인공+여성 원소술사/신성기사 동료2명, 최대3인.
- 15스테이지 구간은 초기무림1·판타지7·귀환무림4·균열/지옥3으로 확정. 상세 서사와 합류 위치3/5는 STORY_DETAILS의 초안이며 아직 본편 코드에 적용하지 않았다.
- 사용자가 보낸 SD 픽셀 캐릭터 참고를 기준으로 `design/mockups/reference-style` 목업을 생성했고 사용자가 승인했다. 큰 눈, 흑백·적색·금색 붓 검객, 먹의 궤적을 유지한다. 이전 `design/mockups/assets`와 `create_assets.py`는 품질 거절된 시안으로 재사용하지 않는다.
- 기본 시스템부터 만들고 소모품→유물→강화는 후속 순서다. 전체 카드100·유물30·소모품15·사건40·업적35·선물6 목표를 삭제하지 않는다.

## 이번 구현

- TypeScript strict / React / Vite. `src/domain` 전투·RNG·지도, `src/content` 초기카드/인물/이야기, `src/application` 명령, `src/persistence` 검증/IndexedDB, `src/presentation` 실제 UI로 분리했다.
- 메인/3슬롯/로비/준비덱/첫장 대화/분기지도/일반전/1사건2선택/카드보상/야영/집행관/판타지 진입 대화를 연결했다.
- 본편은연묵1인. 별도 저장의3인전투연습을 제공한다. 본편동료합류나15스테이지완성으로 오인하지 않는다.
- 초기 카드20종, 직업10+공용20 준비덱, 입장 복사,3인연습50장. 정의/사본/구역분리, 명시적 턴, 기본피해식, 다단/화상/반격/도발/차지취소, 지속/선천성/보존/소멸, 선택버리기/미리보기.
- 클릭/드래그/키보드, 계산 엔진을 공유하는 대상별 예상피해, 로그/더미, 단축키, 저장후새로고침복구, 방/보상중복차단.
- IndexedDB 본편3슬롯·연습debug namespace·설정분리. 명령별 revision 비교/백업/저장을 같은 거래로 처리한 뒤 화면갱신. JSON내보내기/가져오기·잘못된버전/ID/JSON/더미거절.
- 생성에셋3개(캐릭터/적6셀·카드삽화6셀·빈무대), 실제텍스트/버튼별도렌더. 모션설정/효과음설정. 현재동작은CSS표현이며 프레임애니메이션이아니다.

실제 범위/임시 규칙/남은 항목은 [IMPLEMENTATION_V01](IMPLEMENTATION_V01.md)과 [PROGRESS_V01](PROGRESS_V01.md)을 읽는다. 최초 카드 수치와 세부 상태정책은prototype-1 검수값으로 기록했으며 최종 사용자 확정으로 취급하지 않는다. 기존 RULE_PROPOSALS 전체를 자동 승인한 것으로 해석하지 않는다.

## 실행

`cd /workspace/Second && npm ci && npm run dev` → 실행한 환경의 http://localhost:5173. GitHub Pages 주소는 https://taan9448.github.io/Second/ 이다. 메인 → 여정시작 → 빈슬롯 → 원정떠나기. 연습은 로비의 세캐릭터전투연습으로 시작한다.

`npm test`, `npm run build`, dev서버 실행중 `npm run test:browser`. Chromium은기본 `/usr/bin/chromium`, 다른환경은 `CHROMIUM_PATH` 지정. 이 작업환경에서 npm기본캐시경로 쓰기가실패하여 설치 때 `--cache /tmp/cheonoe-npm-cache`를 사용했다. 다른환경의정상기본캐시는 그대로사용한다.

## 검증 상태

엔진·원정·저장 시험 18개와 프로덕션 빌드가 통과했다. 시험은기본식·더미상한·순수미리보기·다단/동시전멸·선천성/보존/지속·필수선택·도발·차지취소·20종카드·지도/RNG·보상1회·저장스키마·동시revision·3슬롯/연습분리를포함한다.

브라우저 검수도 통과했다. 실제 버튼 조작으로 첫 장을 3전투 경로로 완주했고, 덱 교체·단축키·취소·드래그 공격·전투 중 새로고침·보상 선택지 유지·본편/연습 분리를 확인했다. 1280×720 및 1920×1080의 손패10장/적5마리 스트레스 화면도 검수했고 브라우저 콘솔 오류는 없었다. 이전에문서만검증했던 기록은 현재게임검증의증거로쓰지않는다.

## GitHub Pages 수정

사용자가 GitHub 업로드와 Pages 실행 문제 수정을 요청했다. 기존 Pages는 빌드 전 index.html의 /src/main.tsx를 배포하여 실행할 수 없었다. Vite base를 상대 경로로 설정하고 main push 시 시험→빌드→dist 배포하는 .github/workflows/pages.yml을 추가했다. tests/pages.mjs는 /Second/에서만 파일을 제공하는 정적 서버와 Chromium으로 화면·저장·아트·글꼴 경로를 확인한다. npm run build 후 npm run test:pages로 실행한다. 원격 배포 결과는 Actions에서 별도 확인한다.

Pages 검수: 로컬 정적 /Second/ 브라우저 검수 및 18개 시험/빌드 통과. 원격 최초 Actions 배포는 성공했으나 기존 branch/Jekyll 배포가 뒤이어 소스 버전을 배포했다. 사용자가 Settings → Pages → Source를 GitHub Actions로 변경했다고 답변했다. 이후 push에는 branch/Jekyll 배포가 생성되지 않고 전용 빌드 배포만 실행됨을 확인했다. 연결 도구는 Pages 관리 설정을 변경할 수 없다. 재실행 시 중복 artifact 오류를 피하도록 artifact 이름에 run_attempt를 넣는다. 이 환경에서는 github.io 직접 접속이 네트워크 정책으로 차단되어 실사이트 화면은 검증하지 못했다.
