## 2. 단계별 구현

| 단계 | 작업 | 종료 기준 |
| --- | --- | --- |
| P0 | 기본 캠페인·파티·전투·스토리·이벤트·모듈 원정의 초안 | 문서 일관성, 대표 경로 비교, 필수 본편/선택의 경계 확인; 초안 작성 |
| P1 | 구현 지시 후 기본 프로젝트·데이터·RNG·저장, 임시 화면 | 브라우저 부팅·읽기/쓰기·실행 경로; 강화/아이템 없음 |
| P2 | 작은 기본 전투,1인→3인, 공용 덱·턴·더미·피해·승패·입력·로그 | 기본 규칙과 실제 화면 일치; 강화나 유물로 밸런스를 보정하지 않음 |

| P5 | 전투·덱빌딩 확장과 카드100종, 기본 보상·수집·경제·15스테이지 | 기본 파티/원정이 먼저 성립하고 전체 본편·필수 정보 연결 |
| P6 | 소모품→유물→강화·대장간을 각각 별도 설계·구현·검수 | 순서별 구체 규칙 검토,15/30종 효과와 경제·확률/실패, 모든 확장 방 유형 |
| P7 | 이벤트40종 전체 대본·효과, 모드·3슬롯·업적35·선물6·도감·통계·일일/디버그 | 최종 콘텐츠와 장기 진행 요구의 실제 동작 |
| P8 | 최종 픽셀 에셋·화면·밸런스·전체 플레이 검수 | 전체 요구 만족과 실제 실행 경로, 잔여 문제 기록 |

현재는P1~P4의 첫 실행 흐름이 있으며 전체 범위는 아직 진행 중이다. P2~P4가 나중에 실행 가능해져도 전체 게임의 완성이 아니다. 저장은P1부터 고려한다. 초기 원정에 상점·유물·소모품·강화 방을 미작동 상태로 넣지 않는다. 최종 목표는 삭제하지 않고P6~P7로 분리한다.

기본 전투 규칙은P2 전에, 원정/시도/선택 확정 정책은P3~P4 전에 검토한다. 강화·소모품·유물은P6에서 각각 상세 규칙을 정한다. 하드코어 결과는 모드 활성화 전에 검토한다. 현재 구현은 승인되었다. 큰 게임 규칙 변경은 실제 결과를 놓고 검토한다.

## 3. 완료 정의

기능 완료는 데이터, 엔진 효과, UI 조작, 저장/복구, 필요한 검수를 모두 포함한다. 카드 이름/그림만 추가하거나 버튼을 무반응으로 배치한 상태는 완료가 아니다. 기존 코드에 빈 핸들러를 남겨 동작하는 척하지 않는다.

콘텐츠 개수는 `정의됨 / 효과 구현됨 / 검수됨 / 최종 아트 적용됨`을 각각 기록한다. 전체 완료 보고는 요구사항 R01~R08과의 대조를 통과한 뒤 가능하다.
