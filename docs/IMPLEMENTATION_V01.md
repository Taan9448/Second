# 첫 플레이 버전 구현 기준

2026-10-05 사용자가 디자인 목업을 승인하고 게임 제작 시작을 요청했다. 문서만/코드 금지라는 앞선 범위는 해제되었다. 목업 스타일 승인은 모든 카드 수치와 기존 규칙 검토안의 승인을 뜻하지 않는다.

## 실제 범위

- 첫 번째 장의 도입 대화 → 분기 지도 → 일반전 → 사건 또는 전투 → 다리 전투 → 보스 전 야영 → 집행관 → 판타지 진입 대화.
- 본편은 연묵 1인이다. 리엔·세라의 본편 합류는 아직 미구현이다. 3인 파티 검수는 별도 전투 연습에서 가능하다.
- 카드 정의20종(붓6·원소4·신성4·공용6), 정의와 사본 분리. 기본100종의 완료는 아니다.
- 로비에서 연묵10장과 공용20장을 개별 교체. 원정 입장 시30장을 깊은 복사. 연습은3직업각10+공용20=50장이다. 초기 중복 편성 상한을 새로 제한하지 않았다.
- 전투 구역6개, 선천성/보존/소멸/지속, 카드 드로우·에너지·선택 버리기·미리보기, 명시적 턴 단계, 다단 피해·화상·반격·도발·차지 취소·다음 라운드 체력 조건 패턴, 승패.
- 클릭·드래그·키보드가 같은 전투 명령을 사용한다. 대상별 예상 피해는 같은 엔진을 복제 실행한다. 비용 지불 전 Esc 취소, 모든 더미 상세, 로그를 제공한다.
- IndexedDB 본편3슬롯, 연습 별도 namespace, 설정 분리. 상태/난수/결과를 명령마다 저장하고 정상 저장 후에 화면에 공개한다. revision 비교와 이전 정상본 백업을 동일 거래에 기록한다.
- JSON 내보내기/가져오기. 잘못된 JSON/버전/ID/더미/덱 구성은 거절하고 원본을 보존한다. 자동 마이그레이션·백업 복구 UI는 미구현이다.

## 기술 구조와 저장 영향

`src/domain`은 React·DOM·IndexedDB를 import하지 않는다. `content`에 정의, `application`에 게임 명령, `persistence`에 검증/거래, `presentation`에 화면을 둔다. 초기 무대는 DOM/CSS 스프라이트로 표시하고 메인/로비와 공용 화면 부품은 별도 파일로 분리했다. 한글 서브셋 웹폰트를 번들해 OS별 글꼴 차이를 줄였다. PixiJS의 프레임/효과 큐는 필요할 때 독립 렌더러로 확장한다.

새 저장 스키마1·규칙버전prototype-1을 도입했다. 이전 게임 데이터는 이식하지 않는다. 버전을 자동 무시하지 않으며, 향후 콘텐츠·규칙 변경 시 저장 이전을 따로 설계해야 한다. 원정/전투 시드와 RNG는 저장되고 미리보기는 RNG를 소모하지 않는다. 새 원정을 명시적으로 시작할 때만 새 시드를 생성한다.

## 1스테이지 표현 후속 패스

현재 무대는 DOM의 캐릭터 스프라이트와 별도 Canvas 효과 레이어를 사용한다. 연묵 대기/공격 프레임과 먹룡 비행프레임, 적 대기/공격자세, 명중별 체력 표시를 추가했다. 전투 규칙·저장 스키마를 바꾸지 않고 일회성 이벤트에 hpAfter/blockAfter 메타데이터만 보강했다. 정확한 범위·검수·미완료는 COMBAT_FEEL.md에 기록했다. 현재는 1스테이지 느낌 확인 후 나머지 스테이지를 진행한다.
