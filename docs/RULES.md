# 요구사항과 규칙

작성: 2026-10-04, 설계 초안. 사용자가 제공한 프롬프트와 후속 답변이 기준이다. 후속 답변으로 **PC 브라우저 우선**, **이전 데이터를 참고·대조·보존하라는 요구는 모두 무시하고 독립적인 새 게임 개발**이 확정되었다.

갱신: 2026-10-05 최신 요청으로 **승인 목업 기반 게임 제작 시작**이 승인되었다. 실제 첫 버전 범위/검수값은 [IMPLEMENTATION_V01](IMPLEMENTATION_V01.md), 진행은 [PROGRESS_V01](PROGRESS_V01.md)을 따른다. 기본 시스템을 먼저 구현하고 강화·소모품·유물은 후속 순서로 유지한다. 최초 기능 수량을 축소하지 않는다.

추가 확정: 월드맵은 **초기 무림1(1번) / 판타지7(2~8번) / 귀환 무림4(9~12번) / 균열·지옥3(13~15번)**으로 구성한다.

표기: **확정**은 명시된 요구, **제안**은 검토용 권장안, **대기**는 규칙이나 수치가 없어 구현 전에 결정해야 하는 항목이다. 제안을 확정 규칙으로 사용하지 않는다. 이전 코드·확률·단축키를 찾거나 기존 게임에 맞출 의무는 없다.

## 2. 게임 구조

장기 캠페인의 각 스테이지 안에서 분기 원정을 진행한다. 먼저 이야기 진행·파티·준비/스테이지 덱·전투·원정 경로·선택 기록·저장 관계를 설계한다. 최종적으로는 영구 카드 수집과 로비 강화가 있고 원정 중 카드·체력·임시 효과가 변하지만, 강화·아이템의 세부 설계는 기본 원정이 성립한 뒤로 미룬다.

| 계층 | 상태 | 유지 범위 |
| --- | --- | --- |
| 프로필 | 설정, 누적 기록, 업적 정책 | 프로필 범위; 슬롯 합산 여부는 대기 |
| 저장 슬롯 | 고정 모드, 이야기, 동료, 영구 수집·강화, 준비 덱 | 캠페인 전체 |
| 스테이지 원정 | 준비 덱의 복사본, 지도, 현재 체력, 획득·임시 효과 | 해당 스테이지 |
| 전투 | 에너지, 자원, 카드 인스턴스와 더미, 상태, 적, 행동 예고 | 해당 전투 |
| 화면 | 선택 카드, 드래그, 툴팁, 애니메이션 | 표시와 입력 |

## 3. 카드와 덱

**확정**

- 직업별 정의 20종 × 3 = 60종, 공통 정의 40종, 기본 카드 총 100종.
- 직업별 준비 덱 10장, 공용 준비 덱 20장. 현재 편성 직업만 전투 덱에 참여한다.
- 편성 동료의 스테이지 덱 + 공용 스테이지 덱 + 해금된 편성 합동기를 합쳐 셔플한다.
- 합동기는 별도 목록으로 추적한다. 기본 100종에 포함되는지와 추가 종수는 미정이다.
- 입장 시 준비 덱을 스테이지 덱으로 깊은 복사한다. 원정 변화가 준비 덱에 자동 전파되지 않는다.
- 정의 ID와 인스턴스 ID를 분리한다. 카드 종류별 수집과 실제 덱의 개별 사본을 구분한다.
- 등급: 일반/고급/희귀/영웅/전설. 계통: 무공/마법/융합. 소유자·유형·속성·강화·조건·연계·키워드를 구조화한다.

**덱 규모 검토**

| 편성 인원 | 직업 카드 | 공용 카드 | 합동기 제외 총합 | 턴 기본 드로우 |
| --- | --- | --- | --- | --- |
| 1 | 10 | 20 | 30 | 5 |
| 2 | 20 | 20 | 40 | 5 |
| 3 | 30 | 20 | 50 | 5 |

이 규모에서 특정 1장을 첫 5장 안에 뽑을 확률은 선천성 등의 개입이 없으면 각각 약 16.7%, 12.5%, 10%다. 동료가 늘수록 특정 연계 카드의 접근성이 낮아진다. 덱 수치를 변경하기 전에 기본 드로우 그대로 실제 손패 분포와 턴 길이를 시뮬레이션한다. 연계 자원을 턴 사이에 유지하거나 기존 100종 안에 서치/교환 카드를 배치하는 안은 제안이며, 수치를 자동 변경하지 않는다.

**대기**: 동일 종류 중복 편성 상한, 초기 보유 종류와 시작 덱, 직업 10장/공용20장이 고정 장수인지 상한인지, 원정에서 보상으로 늘어난 덱의 한도, 합동기 수·사본 수·투입 방식, 보상 카드의 영구 수집 처리.

## 4. 전투 규칙

### 턴과 카드 구역

기본 에너지 3, 기본 드로우 5, 손패 최대 10은 확정이다. 파티 공용 에너지로 처리하는 안은 제안이며, 캐릭터별 에너지와 구분해 결정한다.

진행 순서는 `전투 시작 → 플레이어 턴 시작 → 카드/소모품/선택 처리 → 플레이어 턴 종료 → 적 순차 행동 → 라운드 종료 → 다음 행동 예고 → 다음 플레이어 턴 시작`이다. 각 단계는 명시적 상태이며 자동 단계에서는 일반 카드 입력을 받지 않는다.

카드 구역은 `draw / hand / discard / exhaust / activePowers`로 분리한다. 효과 처리 중 카드도 `resolving`으로 추적해 어느 구역에도 없는 상태를 방치하지 않는다. 살아 있는 인스턴스는 항상 한 구역에만 속한다.

- 뽑기 더미가 비면 버린 더미만 재셔플한다. 소멸·지속 카드·해결 중인 카드는 들어가지 않는다.
- 손패가 10장일 때 초과 드로우한 카드는 버린 더미로 간다. 드로우 시도 횟수는 유한하게 소모되어 반복 재셔플에 빠지지 않는다.
- 보존, 선천성, 소멸, 임시 카드, 턴별 비용 변경은 각각 필드와 수명으로 표현한다.
- 선천성 카드가 손패 제한보다 많을 때의 순서, 보존 카드가 기본 드로우와 충돌하는 순서는 결정 대기다.
- 선택 버리기/소멸/미리 보기 등은 `PendingChoice` 상태에서 대상과 선택 수를 검증한다. 필수 선택이 끝나기 전 다른 행동을 진행하지 않는다.
- 취소 가능 구간은 비용 지불 전 입력 선택이다. 이미 해결된 무작위 효과나 보상에는 임의 되돌리기를 붙이지 않는다.
- 턴별 비용은 원본 비용과 분리해 종료 시 해당 수명만 만료시킨다. 전투 생성 임시 카드와 원정 임시 카드는 별도 수명이다.

### 피해

사용자가 명시한 기본 공격식은 `floor((기본 피해 + 힘) × 약화 계수 × 취약 계수 × 치명타 배율)`이며 이후 보호막을 차감한다. 약화는 0.75, 취약은 1.5, 비치명타 배율은 1이다.

자원·강화·특성·유물·추가 상태가 없는 기본 공격에서는 위 식과 정확히 일치해야 한다. 피해 10, 힘2, 약화·취약, 치명타 배율1이면 `floor(12×0.75×1.5)=13`; 보호막5이면 보호막5를 소모하고 체력8을 잃는다.

다음 사항은 계산 파이프라인을 설계하되 수치를 확정하지 않는다.

- 강화와 자원의 가산/곱산 위치, 유물 간 순서, 최소 피해, 피해 상한, 치명타 확률·배율.
- 다단히트의 힘 적용 단위, 치명타 판정 단위, 매 타격 사이 반격/상태/사망 처리.
- 일반 공격, 상태 피해, 반사/반격, 체력 지불, 치유의 별도 피해·회복 종류.
- 보호막의 턴 만료 시점, 상태 중첩·지속시간과 감소 시점, 도발 우선순위.

**제안**: 각 타격을 개별 해결해 보호막과 트리거를 실제 순서대로 반영한다. 미리보기와 실전은 같은 계산 함수를 사용한다. 무작위 치명타는 확정 수치로 표시하지 않고 확률/범위로 표시한다.

### 적과 전투 종료

- 동시 적 최대 5. 소환 시 남은 슬롯을 검증한다. 초과 소환의 실패/대기 정책은 결정 대기다.
- 예고에는 실제 피해, 횟수, 대상, 부가 효과를 포함한다. 도발이나 상태 변화로 대상·피해가 바뀌면 예고도 갱신한다.
- 차지 취소, 체력 조건 패턴 전환, 소환, 변이, 보스 기믹을 데이터와 상태 전이로 모델링한다.
- 승리: 적 전멸. 패배: 편성 동료 전원 쓰러짐.
- 상태 피해·반격·소환은 효과 큐와 사망 처리 규칙을 공유한다. 마지막 적의 사망 트리거가 소환을 만들 수 있으므로 사망 순간에 바로 승리 보상을 만들지 않는다.
- 승패가 동시에 성립하는 경우, 해결 중 소환을 포함한 전멸의 판단 시점은 별도 확정이 필요하다. 종료는 한 번만 기록한다.
- 동료가 쓰러졌을 때 그 동료 소유 카드·공통 카드·합동기를 어떻게 처리할지 대기다. 제안은 사용 불가 사유 표시 + 손패 정리 수단이지만 임의 무료 버리기 규칙을 추가하지 않는다.

### 입력·관측

클릭+대상 클릭, 드래그+대상 지정, 선택 취소, 사용 불가 사유, 피해 미리보기, 전투 기록, 모든 더미 상세는 실제 명령으로 연결한다. 키보드는 같은 명령 경로를 사용한다. 단축키는 새로 설계한다.

## 5. 파티의 차별성 — 제안

주인공은 붓끝에 검기를 모으는 검객, 동료1은 불·전기·얼음을 쓰는 원소술사, 동료2는 신성력·방패술을 쓰는 신성기사다. 모두 여성이다.

| 캐릭터 | 제안 자원 | 전투 역할 | 연계 방향 |
| --- | --- | --- | --- |
| 주인공 | 묵흔/필세 | 표식, 다단 공격, 무공·마나 융합 | 원소 표식을 붓으로 연결, 방패 반격에 추격 |
| 원소술사 | 원소 잔향 | 화상·전도·빙결, 원소 순서 조합 | 표식 확산, 냉기 보호막, 전기 추격 |
| 신성기사 | 성휘/서약 | 보호막, 도발, 회복, 반격 | 아군을 보호하며 합동기 자원 제공 |

자원 생성·소모, 중첩 상한, 턴간 유지, 합동기 조건은 밸런스 문서에서 결정한다. 속성 효과를 이름만 만들고 구현된 것으로 보고하지 않는다.

## 6. 강화·경제

**후속 단계로 보류.** 아래는 최초 프롬프트의 최종 목표이며 이번 초기 시스템 설계에서 비용·확률·실패 수치를 정하지 않는다. 이전 RULE_PROPOSALS의 비용/확률 표는 미승인 초안이었고 이번 지시로 철회했다. 기본 전투를 수치상 성립시키는 데 강화가 필요하지 않도록 설계한다.

- 최대 강화 +10. 원정 휴식/이벤트 강화는 최대 +3, +4~+10은 로비 대장간에서만 가능하다.
- 비용, 등급 배율, 성공 확률, 실패 하락, 하한을 단계별 표로 저장한다.
- 실행 전 현재/결과 단계, 최종 비용, 성공률, 실패 결과를 표시한다. 같은 계산 결과를 실제 거래에 사용한다.
- 강화 확률·비용은 기본 시스템과 경제가 잡힌 뒤 새 게임의 수치안으로 설계한다. 확정 후 임의 변경하지 않는다.
- 시도 ID, 비용 차감, RNG 진행, 강화 결과는 한 거래로 저장한다. 새로고침으로 비용이나 결과를 다시 계산하지 않는다.
- 영구 강화와 원정 강화의 관계는 대기다. 제안은 영구 강화값을 입장 시 복사하고 원정 강화는 해당 사본에만 적용하는 방식이다. 영구 +4 이상인 사본을 원정에서 +3으로 낮추지 않는다.

## 7. 원정·지도·아이템

원정 모듈과 이벤트의 상세 초안은 [EXPEDITION_MODULES](EXPEDITION_MODULES.md), [EVENT_STORIES](EVENT_STORIES.md)를 따른다. 모듈 재조합·방 내용 변화·연속 사건이 반복 경험을 만든다. 고정 본편과 필수 정보는 추첨에서 제외한다. 아래 상점·강화·유물·소모품·아이템 보상은 최종 확장 범위이며 초기 원정의 전제에서 제외한다.

- 월드맵 15스테이지, 각 던전은 경로 모듈로 만든 분기 그래프다. 연결된 다음 방만 선택 가능하다.
- 미지/정찰은 정보 상태, 현재/완료/잠김은 진행 상태로 나눠 동시에 표시할 수 있게 한다.
- 전투·정예·중간 보스·보스·이벤트·보물·휴식·상점·카드 선택/강화/정리, 보물 매복, 방 종류 제한, 보스 전 야영지를 모두 연결한다.
- 지도·상점 재고·이벤트·보상 선택지는 생성 시 결과를 저장한다. 소비·선택 완료 ID도 저장해 반복 지급을 막는다.
- 내부 전투 간 체력 유지, 스테이지 간 체력 회복, 일반 모드의 쓰러진 동료 전투 후 복귀는 요구다. 회복량·복귀 체력·패배 손실·재도전 완화 수치는 대기다.
- 로비 편성과 스테이지 클리어 직후 합류를 제안한다. 전투 중 편성은 허용하지 않는 안이다. 스테이지 도중 합류를 선택한다면 안전 지점과 덱 추가 방식도 별도 결정해야 한다.
- 유물 30종. 시작/턴/카드/회복/처치/피격/소멸/보상 트리거 및 보스 유물의 이점과 대가를 구현한다.
- 소모품 15종, 기본3슬롯. 플레이어 턴의 허용 시점에 에너지 없이 사용하고 제거한다. 사용 중 선택 대기 상태와 트리거 해결 상태를 구분한다.
- 소모품 드롭·구매·슬롯 초과·버리기·되돌리기 정책은 새로 설계한다. 제안은 초과 시 명시적 교체/포기 선택이며 자동으로 기존 아이템을 버리지 않는다.
- 이벤트40종은 연속 이야기8개×4장면과 독립 사건8개의 초안으로 기획했다. 초기에는 인물·기록·경로·대피·후일담 선택으로 구성한다. 최종 확장에서는 비용/이득·임시 효과·특수 전투·카드/유물/소모품/친밀도 결과를 연결한다. 거울의 방의 카드 복제 효과와 수치형 친밀도는 후속 검토다.

## 8. 장기 진행·저장

- 노말/하드/하드코어는 저장 슬롯 생성 때 고정한다. 난이도 수치와 접근 조건은 대기다.
- 하드코어는 전투 종료 시 쓰러진 동료가 영구 사망한다. 전투 중 되살아난 동료를 종료 시 사망으로 처리하지 않는다. 승리/패배 양쪽 종료 경로를 검증한다.
- 주인공도 영구 사망하는지, 주인공 사망/전멸 시 저장 종료와 슬롯 보존 정책은 대기다. 불명확한 상태로 플레이를 허용하지 않는다.
- 업적35종, 시작 선물6종, 누적 기록, 카드별 통계. 미획득·미조우 도감은 설명·이미지·이름 노출 범위를 명세한다.
- 저장3슬롯, 자동 저장, 설정, 프로필, 일일/디버그 저장을 분리한다. 본편 슬롯이 일일/디버그 결과로 변경되지 않게 한다.
- 잘못된 ID·버전·JSON·저장 불가 환경·중단된 저장을 검증한다. 오류가 발생한 저장을 덮어쓰기나 자동 초기화로 지우지 않는다.
