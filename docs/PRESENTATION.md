# 화면과 픽셀 아트

2026-10-05 최신 요청으로 **SD 픽셀 디자인 목업이 승인**되었고 게임 제작이 시작되었다. 실제 브라우저 UI, 캐릭터6셀·카드6셀·무대 에셋을 제작했다. 최종 프레임 아트는 후속 작업이다. [첫 버전 진행표](PROGRESS_V01.md)를 따른다.

아래 초기 화면/규격은 장기 검토안이며, 사용자 지정 SD 스타일과 승인 목업이 우선한다. 미작동 강화·소모품·유물 버튼은 넣지 않는다.

## 1. 표현 방향

무림은 먹색·청록·낡은 종이, 판타지는 깊은 남색·원소색·은빛, 균열은 자주·갈라진 백색을 사용한다. 상용 게임은 조작·정보 전달의 비교 대상으로만 삼고 카드 테두리·캐릭터·아이콘·화면 구성은 자체 제작한다.

붓 검객은 긴 필관, 원소술사는 짧은 망토와 원소 고리, 신성기사는 큰 방패로 작은 실루엣에서도 구분한다. 불은 주황 삼각·전기는 노랑 번개·얼음은 파랑 결정으로 색 외에 형태를 함께 사용한다. 생존·쓰러짐·영구 사망도 색만으로 구분하지 않는다.

## 2. 전투 화면 배치안

PC 1280×720을 첫 검토 기준으로 삼되 최종 승인 전이다. 화면 크기가 달라져도 손패·버튼·정보가 겹치지 않게 반응형 HUD와 무대 스케일을 분리한다.

```text
┌───────────────────────────────────────────────────────────┐
│ 스테이지/라운드   자원·유물   소모품3슬롯   로그·설정     │
├───────────────────────────────────────────────────────────┤
│ 아군3인: 체력·보호막·개인자원   적≤5: 대상·피해·횟수·효과 │
│                                                           │
│                 픽셀 전투 무대                            │
│                                                           │
├───────────────────────────────────────────────────────────┤
│ 뽑기/버림/소멸/지속   에너지3   카드 선택/취소   턴 종료   │
│                   손패 최대10장                           │
└───────────────────────────────────────────────────────────┘
```

카드를 선택하면 유효 대상 강조·불가 이유·시전자·비용·피해 계산 내역을 보여 준다. 손패10장은 겹침 폭을 조절하고 호버/키보드 포커스 카드가 확대되게 한다. 미리보기와 툴팁은 조작을 가리지 않는다. 드래그 실패 시 카드를 손패로 돌리고 비용을 지불하지 않는다.

적5마리의 예고를 모두 읽을 수 있어야 한다. 숫자·아이콘·대상 이름을 함께 표시하고 도발·차지 취소 뒤 즉시 갱신한다. 마지막 보스나 작은 화면에서는 무대를 줄여 HUD 가독성을 우선한다.

선택 버리기/소멸/미리 보기는 별도 선택 패널에 선택 수·취소 가능 여부·확정 버튼을 표시한다. 키보드에서도 동일한 패널과 명령을 사용한다.

## 3. 화면 흐름

`타이틀 → 3슬롯/모드/선물 → 도입 → 1스테이지 초기 무림 원정 → 판타지 이동 → 로비 → 편성/덱/대장간 → 월드맵 → 원정 지도 → 방 → 보상 → 지도 → 보스 → 스테이지 정산 → 로비`.

세계 구간은1스테이지 초기 무림, 2~8 판타지, 9~12 귀환 무림, 13~15 균열·지옥이다. 세계 이동 연출은 해당 스테이지 완료 상태와 같이 저장해 복구 시 중복 해금하지 않는다. 도입 이전/1스테이지의 로비 기능 개방 시점은 스토리·초기 온보딩과 함께 구체화한다.

상점, 이벤트, 보물 매복, 휴식, 카드 정리는 같은 원정 상태로 복귀한다. 소모품 초과·보상 확정·영구 사망·원정 패배는 결과와 다음 선택을 명시한다. 로비에서는 카드 수집과 현재 편성 덱을 구분해 보여 준다.

## 4. 새 단축키안

| 키 | 동작 |
| --- | --- |
| 1~9, 0 | 손패1~10 선택 |
| Esc | 미확정 카드·대상 선택 취소; 필수 효과 선택은 규칙에 따름 |
| E | 턴 종료; 필수 선택이나 자동 처리 중에는 비활성 |
| Q/W/R | 소모품1/2/3 선택 |
| D | 뽑기 더미 |
| F | 버린 더미 |
| X | 소멸 더미 |
| P | 사용된 지속 카드 |
| L | 전투 기록 |
| 방향키/Tab/Enter | 포커스 이동·선택·대상 확정 |

텍스트 입력 중에는 전투 단축키를 받지 않는다. 실제 플레이에서 충돌을 확인하고 변경 가능 설정을 검토한다. 키표만 적어 놓은 상태는 구현 완료가 아니다.

## 5. 이미지 없이 가능한 작업

텍스트·CSS 카드, 색 블록/실루엣 캐릭터, 도형 이펙트, 무대 좌표, 입력·예고·미리보기·더미·로그를 먼저 구현할 수 있다. 이 자료는 **임시 표시**이며 최종 아트로 보고하지 않는다. 사용자의 이미지 생성 사용량을 소모하는 도구는 오늘 호출하지 않는다.

무대의 프레임 애니메이션 상태 기계와 에셋 manifest는 미리 만들 수 있다. 임시 애니메이션이라도 실제 판정과 연결되는 명령 경로는 동일하게 유지한다.

## 6. 에셋 제작 규격안

- 캐릭터 기본 캔버스64×64, 신체 실루엣 높이48~56픽셀. 적은 크기별 규격과 기준점 정의.
- nearest-neighbor 정수 배율, 동일 팔레트와 바닥 기준점. 배경과 HUD 스케일은 분리.
- 최초 제작 상태: idle/move/attack/cast/hit/guard/down/victory. 인물별 고유 공격은 별도 clip.
- clip마다 atlas, frameRects, pivot, fps 또는 frame durations, loop, visual markers를 manifest에 기록.
- visual marker는 붓 흔적·번개·방패 섬광 시점을 맞추며 게임 피해를 계산하지 않는다.
- 불·전기·얼음·신성·먹검기·균열 효과는 자원 표시와 같은 모양 체계를 사용.
- 초상화·전투 스프라이트·카드 그림은 동일 캐릭터 모델 시트를 기준으로 제작.

64×64는 제작 시안이며 확정 규격이 아니다. 이미지 생성 결과가 바로 정확한 스프라이트 시트라고 가정하지 않는다. 프레임 정렬·캐릭터 일관성·투명 배경·픽셀 크기·라이선스/출처를 확인하고 엔진에서 재생 검수한다.

## 7. 다음 화면 승인 기준

동료3인/적5/손패10/소모품3/상태 다수를 넣은 실제 브라우저 임시 화면을 만든 뒤 가독성·클릭·드래그·키보드·픽셀 분위기를 검토한다. 화면 승인은 이 구체적인 결과에 대해 요청한다. 승인된 레이아웃은 별도 디자인 변경 없이 콘텐츠 확장에 사용한다.

## 최신 사용자 지시와 목업 (2026-10-05)

사용자가 제공한 고밀도 SD 픽셀 캐릭터를 시각 기준으로 지정했고, 이미지 생성 제한 해제 후 실제 목업 생성을 요청했다. 이전 문서의 이미지 제작 보류는 해제되었다. 흑백·적색·금색 붓 검객과 약 2.5등신의 표현을 우선한다. 64×64는 확정 규격이 아니며 이 품질에 맞춰 재검토해야 한다. [디자인 목업](../design/mockups/README.md)은 화면 승인 전 이미지 시안이다. 실행 가능한 UI나 프레임 애니메이션은 아니다. 이전 수작업 임시 아트는 품질 거절되어 사용하지 않는다.
